# Synthetic assessment data

`tools/synth/generate.py` creates two files: canonical assessment events that can be replayed by the gateway and a separate labels file that must not be sent as part of the assessment request. It generates synthetic account/device/beneficiary references and deliberately emits no phone numbers, names, or copied customer data.

```sh
python3 tools/synth/generate.py --count 1000 --seed 7 --out synthetic.jsonl
python3 tools/replay/replay.py synthetic.jsonl --labels synthetic.labels.jsonl
```

The default fraud share is 6%. If the requested share would produce fewer than five positive rows, the generator raises it to five so each pattern is represented (unless `--fraud-rate 0` is specified). The five labels correspond to starter policy patterns:

- `sim_swap_account_takeover`: recent SIM swap, first-seen device and beneficiary, and a high-value transfer.
- `beneficiary_velocity_abuse`: multiple transfers and new beneficiaries in a short window.
- `balance_drain`: a high balance-drain ratio.
- `young_account_fan_in_out`: a young account with high inbound fan-in and rapid outbound activity.
- `agent_float_structuring`: rapid agent float movement with multiple transfers and beneficiaries.

The seed and `--as-of` timestamp make the output reproducible. The default reference time is `2026-01-01T12:00:00+03:00`; pass another timezone-aware timestamp to shift the synthetic period. The event file contains no `confirmed_fraud` or typology fields, so it remains compatible with the strict assessment event schema. Those labels appear only in the sidecar, keyed by `tenant_event_id`.

The replay report includes overall recall, false-positive rate, precision and latency, plus confusion counts by typology. This is a smoke-data pipeline check only: the cohorts are rule-shaped, the labels are generated by construction, and the results do not estimate real fraud performance or customer impact.
