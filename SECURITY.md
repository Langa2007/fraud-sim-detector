# Security policy

Do not report vulnerabilities in public issues. Send a private report to the repository security contact configured in GitHub, including affected version, impact, and a reproducible description. Do not include real customer records or credentials.

The maintainers will acknowledge receipt, coordinate a fix and disclosure timeline with the reporter, and publish remediation guidance after affected deployments can upgrade. For an active data exposure or compromised key, use the incident contacts in the applicable member agreement immediately rather than waiting for a software disclosure process.

Phase 4 security certification is not complete until an independent penetration test is commissioned, critical/high findings are closed, and the report is reviewed by the accountable security owner. This file is not a certification claim.
